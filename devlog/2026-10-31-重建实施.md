# 2026-10-31：重建实施

## 范围

用户要求完成整个重建并得到可用 Windows 构建。实现依据[项目计划](../docs/项目计划.md)、[交互规格](../docs/交互规格.md)、[架构决策](../docs/架构决策.md)。主线程 Tk、统一控制器、后台串行用例、保留运行实例；运行管理与桌面界面按共享接口分别实施，最终统一集成验证。

## 已复现的原问题

在临时 APPDATA 下创建旧 ProcessManager，并让其 GUI 对象管理一个可控 Python 子进程。调用旧 `rebuild()` 后观测：

- rebuild 前 `gui_running()` 为 True。
- rebuild 后 `gui_running()` 为 False。
- 原子进程实际仍存活。

试验随后 terminate/wait 清理该子进程并还原 APPDATA。该输出证明原实现会失去进程管理关系，而不是单纯界面显示问题。

## 实施决策

- 系统自启自动挂载只在 `--autostart` 且全局/逐项允许时执行；GUI 自动启动为随应用启动偏好。
- 保存配置失败保护原文件；文件 checksum 比较和 revision 拒绝外部/在途覆盖。
- 系统自启交易保留注册表原值及类型，失败恢复原值而非生成新的命令代替用户设置。
- 密码采用 DPAPI，rclone 输出在落盘前脱敏，浏览器入口不含凭据。
- 旧 Monitor 线程与后台 Tk 窗口路径由主线程消息泵替代。
