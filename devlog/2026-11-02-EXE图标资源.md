# EXE 图标资源缺失修复（2026-11-02）

## 现象

程序的文件图标不见了：资源管理器、开始菜单、桌面快捷方式中的 `rclone_tray.exe` 显示为通用空白图标。托盘图标与窗口图标正常。

## 根因

- `build.rs` 只读取 git 信息并写入 `RT_BUILD_*`，从未编译 `assets/icon.ico`，链接产物没有任何资源节。
- 用 PE 节表核对 `dist\rclone_tray.exe` 与已安装的 2.1.1：均只有 `.text/.data/.rdata/.pdata/.xdata/.bss/.idata/.tls/.reloc`，**没有 `.rsrc`**。
- 托盘与窗口图标走 `src/host.rs::load_icon`，用 `include_bytes!` 在运行时 `CreateIconFromResourceEx`，所以不受影响；缺失的只有 Shell 从 PE 资源读取的文件图标。
- Windows 的 `ExtractAssociatedIcon` 对无资源 EXE 仍会返回系统通用图标，因此旧探测“返回 32×32”不能证明图标存在。

## 修复

- 新增 `assets/app.rc`：`1 ICON "assets/icon.ico"`。
- `build.rs`：Windows 目标下定位 `windres`（`WINDRES` 环境变量 → `PATH` 中的 `x86_64-w64-mingw32-windres.exe`/`windres.exe` → 链接器同目录），把 `assets/app.rc` 编译为 COFF 资源对象，`cargo:rustc-link-arg-bins` 链接进主程序；非 GNU 目标只提示不中断。
- 找不到 `windres` 时直接失败并给出可执行提示，不再静默产出无图标 EXE。
- 版本提升到 2.1.2，`Cargo.lock` 同步。

## 验证

- `.\tools\build.ps1 -Test` 通过（测试先于构建，失败会中止），产出 `dist\rclone_tray.exe` 2303488 bytes、`dist\rclone_tray_setup.exe`。
- 新 EXE 节表包含 `.rsrc`；资源目录含 `RT_GROUP_ICON`(1) 与 9 个 `RT_ICON`，尺寸 16/20/24/32/40/48/64/128/256，全部 32bpp。
- `[System.Drawing.Icon]::ExtractAssociatedIcon` 取出的图标渲染为蓝底白云图案（应用图标），非通用图标。
- 隔离数据目录（`RCLONE_TRAY_DATA_DIR`）运行新 EXE：进程存活，`Shell_NotifyIconGetRect` 返回 `hr=0x0`，托盘图标矩形非空，说明运行时图标链路未受影响。

## 限制

- 未覆盖 Windows 图标缓存不刷新的情况；覆盖安装后若仍显示旧图标，需重启资源管理器。
- 安装包本身的图标由 Inno Setup 的 `SetupIconFile` 提供，与本次 EXE 资源独立。
