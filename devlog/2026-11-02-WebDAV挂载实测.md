## 驱动方式

`tools/capture_ui.py` 的 ctypes 方案依赖同完整性级别的 Python，但本机 `.venv` Python 进程被系统压到 Low 完整性（`S-1-16-4096`），既不能写 `%APPDATA%`，也无法向 Medium 的应用窗口投递输入。改用 PowerShell + Win32 直驱动：

- `EnumWindows`/`GetClassName` 按类名 `RcloneTray.Frontend` 绑定 PID 对应窗口；
- `LB_SETCURSEL` + `WM_COMMAND(MOUNT_LIST, LBN_SELCHANGE)` 选中 `204` 列表第 0 行；
- `WM_COMMAND(213=START)` / `WM_COMMAND(214=STOP)` 触发启动与停止；
- 状态读取用跨进程 `WM_GETTEXT`（`GetWindowText` 对 `Edit`/`ListBox` 只返回标题，读到空串）。

脚本为一次性驱动，位于 `target/tmptest/mount_smoke.ps1`（`run_smoke_elevated.ps1` 为提权包装）。

## 关键发现：非提权启动时为 Low 完整性

未提权时，应用在启动挂载前即失败，详情为 `创建临时文件失败（系统错误 5）…原配置未被重置。`（首次启动还缺少版本号，底部只剩 `· GUI 已停止 · 空闲`）。逐项排除结果：

- 目标目录本身可写：PowerShell（Medium）可在 `%APPDATA%\rclone_tray\temp` 与 `%APPDATA%\rclone_tray_probe` 建删文件；
- 指定 `RCLONE_TRAY_DATA_DIR` 指向同一真实目录、或指向全新目录，应用仍然报错误 5（`创建应用数据目录失败`）；
- 经 `explorer.exe` 启动（脱离工具令牌与作业对象）同样失败，因此不是本工具沙箱导致；
- 进程令牌实测：`rclone_tray.exe` 完整性 `S-1-16-4096`（Low），同环境 `notepad.exe`、`powershell.exe`、`explorer.exe` 均为 `S-1-16-8192`（Medium）；用户 SID 相同（`S-9-3-59-…`）。

即：挂载失败与“未签名”无关，而是**进程被以 Low 完整性启动**；Low 无法写入 Medium 标记的 `%APPDATA%`，版本探测与挂载前置的临时文件创建直接返回 `ERROR_ACCESS_DENIED`。以 `Start-Process -Verb RunAs` 提权（High）后一次通过全部 12 项检查，WinFsp 层面同理（Low/受限令牌下 `The service rclone has failed to start (Status=c0000022)`）。

## 根因与修复：`E:\items\nether` 带 Low 完整性标签

继续排查后定位到 NTFS 强制性标签，而不是安全软件或未签名策略：

```
icacls "E:\items\nether"
    Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)      ← 显式，向下继承
```

同一份字节的 EXE，放在带 Low 标签的仓库目录启动得到 `S-1-16-4096`，放在未打标签的 `E:\tools` 启动得到 `S-1-16-8192`；对照实验在临时目录复现并修复：

| 实验 | 结果 |
| --- | --- |
| 新建目录并 `icacls /setintegritylevel (OI)(CI)L` 后启动其中的 `rclone_tray.exe` | `S-1-16-4096`（Low） |
| 同目录执行 `icacls /setintegritylevel (OI)(CI)M` 后再次启动 | `S-1-16-8192`（Medium） |

修复（管理员，一次性）：

```powershell
icacls "E:\items\nether" /setintegritylevel "(OI)(CI)M"
# 或
powershell -ExecutionPolicy Bypass -File tools\fix-integrity-label.ps1 -Root E:\items\nether
```

修复后 `E:\items\nether` 标签为 `Medium (OI)(CI)`，其下 EXE、`rclone.exe`、`.venv\Scripts\python.exe` 均以 Medium 启动；**未提权**再次执行同一驱动，12 项检查全部通过（[未提权驱动日志](../docs/evidence/mount-webdav-102-unelevated.log)，`exit=0`）：

| 检查 | 未提权结果 |
| --- | --- |
| 版本探测 | 底部显示 `1.74.0 · GUI 已停止 · 空闲`（此前缺失） |
| 挂载启动 | 详情 `已就绪 · PID …`、`已验证本实例 PID，挂载根目录可访问` |
| 盘符与读写 | `Z:\` 列出 7 个目录；写入/读回/删除成功；`FUSE-rclone`、卷标 `102` |
| 停止 | `已停止、确认卸载并恢复原空目录`；`Z:` 消失 |

注意：`E:\items\nether\projects` 与仓库根目录此前被一次中断的递归操作留下了显式 `Medium` 标签（无继承位），当前语义仍是 Medium；若之后沙箱/代理重新给工作区打 Low 标签，重跑上述脚本即可。

`tools/fix-integrity-label.ps1` 会先检查标签，发现 Low 才通过 UAC 提权修复，修复后再次打印标签状态。
