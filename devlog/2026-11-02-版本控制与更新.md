# 版本控制与更新模块（2026-11-02）

## 目标

为 2.1.0 增加可追溯的版本信息、GitHub Releases 更新提醒、一键下载入口与安装程序，并补齐仓库的版本控制与发布流程。

## 实现

- `build.rs`：编译时读取 git 短提交、分支、未提交修改标记与时间戳，写入 `RT_BUILD_*` 环境变量；git 不可用时降级为 `unknown`，不阻断构建。
- `src/version.rs`：语义化版本解析与比较（主/次/修订 + 预发布标识），Unix 时间到 UTC 文本，构建摘要。无新增 crate。
- `src/update.rs`：WinHTTP GET `api.github.com` Releases 列表；忽略草稿与预发布，选择最高正式版本；校验发布页和资产链接只属于本仓库；优先 `rclone_tray_setup.exe`，其次 `rclone_tray.exe`。连接 4 秒、接收 8 秒、响应上限 2 MiB。只读，不下载或替换 exe。
- `contracts/backend`：`Snapshot.update`、`Command::CheckUpdate { quiet }`；启动后自动检查一次（quiet 失败不弹错误气泡）；手动检查走同一操作队列，busy key 为 `update`。
- `host`：`Available` 状态且版本未提醒过时发送一次 `NIIF_INFO` 托盘气泡；错误气泡保留原行为。
- `ui`：关于页新增更新状态框、“检查更新”“打开下载页面”；状态区分检查中、已是最新、发现新版本、失败；下载按钮只在有已验证链接时启用；诊断文本加入构建摘要。
- `tools/installer.iss`：Inno Setup 6，按用户安装到 `%LOCALAPPDATA%\Programs\rclone_tray`，开始菜单与 HKCU 卸载入口，可选桌面快捷方式，覆盖升级，卸载保留用户配置。
- `tools/build.ps1`：从 `Cargo.toml` 读取版本，定位 `ISCC.exe`，产出 `dist\rclone_tray_setup.exe` 与 SHA-256，并把安装包大小/哈希和 git 提交写入 `build-manifest.json`。
- `tools/release.ps1`：校验干净工作区、版本一致、标签不存在；构建与回归测试后创建 annotated tag，默认推送。
- 版本号提升到 2.1.0；新增 [版本与发布](../docs/版本与发布.md)。

## 验证

- `.\tools\build.ps1 -Test`：36 项单元测试通过（新增版本比较、时间格式、Releases 解析、URL 校验与本地 WinHTTP 读取）。构建产出 2,284,544 字节 exe 与 21,568,663 字节安装包（SHA-256 `019ade410eb6759e50916b8854ed1f2ac31e6deedbd7890455ad21a60276b4ea`）。
- 真实 GitHub 检查：`state=UpToDate latest=2.0.0 message=已是最新版本 2.0.0。`，证明 WinHTTP、TLS、JSON 与版本比较在真实网络可用。
- 真实窗口烟测：启动 `--show`，切到“关于与诊断”，读取控件 513：`当前：2.1.0 · 511bddf7 · main · 2026-11-02 05:29 UTC · 含未提交修改`，状态显示“本地版本 2.1.0 高于最新发布 2.0.0”，与 GitHub 事实一致。截图见 [宽窗](../docs/evidence/native-2.1-update-about.png) 与 [窄窗](../docs/evidence/native-2.1-update-about-narrow.png)。
- 托盘气泡链路由同一快照状态驱动；本次未在无前端场景人工等待气泡，未宣称已目视验证。
- Inno Setup 编译成功并生成安装包；在本机执行安装到临时目录时，安装程序完成文件复制后创建 `HKCU\...\Uninstall` 失败（错误 5）。同一沙箱下复制的 `powershell.exe` 也出现 HKCU 写入被拒绝，确认是当前工具进程的沙箱限制，不是安装脚本逻辑；未在本环境完成安装/卸载全流程验收。

## 限制与后续

- 更新检查只读：安装仍需运行下载的安装程序。若以后要自更新，需要替换运行中 exe 的助手进程与签名/哈希校验，当前未实现。
- GitHub 未认证 API 每小时 60 次；启动检查每次应用启动一次，手动检查受 busy 去重。
- 发布 2.1.0 时需上传安装包；旧 `v2.0.0` 资产仍是历史 Python 构建，更新模块只按版本比较，不会把 2.1.0 降级到它。
