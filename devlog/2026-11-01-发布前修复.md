# 2026-11-01：发布前审查修复（v2.0.0）

## 背景

界面重构完成后准备发布。发布前做了一轮独立代码审查（只读评审，未改动文件），随后按评审结论修复发布阻塞问题，再重新构建并验证打包产物。

## 评审结论与处理

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | `gui_no_auth` 默认 `True`，新用户开箱即以 `--no-auth` 把 rclone RC API 暴露在本机 5572 端口；RC 等价于本机命令执行权限 | **已修**：默认 `False`（需要用户名/密码）。保存设置不再因缺凭据而失败，凭据校验移到启动 GUI 前；服务页提示改为说明免认证的实际风险 |
| 2 | 自动发现的 rclone 路径被写回配置文件。单文件版内置 rclone 位于 `%TEMP%\_MEIxxxx`，下次启动该目录已不存在，导致“未找到有效 rclone”且无法保存设置 | **已修**：`Controller` 用 `_exe` 单独保存解析结果，`refresh_environment`/`_validate_settings` 都不再改写 `cfg.rclone_path`；设置页与诊断显示解析到的程序路径 |
| 3 | 异常终止（崩溃、任务管理器结束）后 rclone 子进程残留，应用拒绝接管外部实例 | **未修**（记录为已知限制）：需要 Job Object 接管子进程生命周期，属于新增系统集成，未在发布前改动。README 写明排查方式 |
| 4 | 保存任意设置会取消开机自动挂载的延迟任务，且不重新计时 | **已修**：记录计划时间点 `_mount_deadline`，保存成功后按剩余时间重新计时；关闭“开机自动挂载”仍会取消 |
| 5 | 短凭据（如单字符用户名）参与整词脱敏，把日志与状态消息替换成 `[redacted]` | **已修**：仅对长度 ≥ 4 的凭据做整词替换，短值交给正则规则 |
| 6 | Tk 事件泵没有异常保护，一次刷新异常就停止投递结果，界面表现为假死 | **已修**：泵体 `try/except` 记录异常后继续下一帧；`root.after` 仅在窗口仍存在时重新挂载 |

评审同时确认：凭据不进入日志/URL/诊断；进程不会重复启动，停止失败不丢所有权；配置写入为临时文件 + `fsync` + `os.replace` + 校验和比较，未知字段/缺字段/类型错误/重复键都会拒绝而不是重置。

## 变更文件

- `core/config.py`：`gui_no_auth` 默认值。
- `core/processes.py`：`_safe_text` 短凭据处理。
- `app/controller.py`：`_exe` 与 `snapshot()["exe"]`、不改写自动发现路径、保存后重新计时自动挂载、凭据校验移交启动阶段。
- `main.py`：事件泵异常保护。
- `ui/settings_window.py`：解析到的程序路径显示、免认证提示文案。
- `README.md`：认证默认值与自动发现不落盘的说明。
- `tests/`：新增 5 项回归（路径不落盘、保存后保留挂载计划、短/长凭据脱敏、默认需要认证），共 18 项。
